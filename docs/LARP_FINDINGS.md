# LARP：实跑发现、提升与消融结论

本页总结**历史实际训练结果**，不是本次 Git 发布后新增的 GPU 实验。最终主方案始终是后四层、O-only、rank2 的 `O4-r2`；不按消融最高分事后更换主方法，也不将不同候选的最好数据集拼成一个方法。

结论先说清：主方案在 **7/10 个数据集的三 seed 平均 HM 上同时超过 R0 与 R1**，达到预设的方向性覆盖目标；但十集等权 HM 宏平均为 **83.9526%**，相对 R0 为 **+0.0807 pp**、相对匹配 R1 为 **−0.3046 pp**。因此有具体任务上的有效改善，不能概括为整体平均优于匹配基线、普遍稳定或统计显著。[逐次结果](../results/larp/flat_results.json)、[完整汇总](../results/larp/analysis.json)

## 1. 研究问题与最终保留的处理

研究问题是：保留 PromptKD 的视觉提示、投影器、冻结教师和原蒸馏目标，仅给学生注意力的输出映射增加低秩自由度，能否改善具体任务的 Base/Novel 识别平衡？还需区分“结构确实有收益”“公共训练协议改变带来的差异”及“训练波动/数值问题”。

| 发现或需要避免的问题 | 最终保留的处理 | 结论边界 |
| --- | --- | --- |
| 历史源目录的 V-only 默认配置不等于最终实际 O-only 实验 | 发布入口按最终配置合同解析 O-only、后四层 rank2；只参数化 `out_proj.weight`，保留原 MHA 前向 | 修正的是运行入口与实验身份，不能把旧默认配置的结果当成最终 O 的结果，也不由此证明 O 在所有任务优于 V |
| 新增参数抽样、公共投影器调度可能影响配对比较 | 新增模块初始化使用 RNG 隔离；R1/候选核共同初态和全 batch 输入；共同投影器第 2 轮渐升两者都有 | R1 是匹配控制，不是官方 R0；本组结果没有单独证明渐升或某个工程组件的独立收益 |
| 低损失、较好 best 分数与稳定训练不是同一件事 | 保留 20 轮全轨迹、有限性检查、Base 首次最高选点和首次独立重载；负结果不删 | 原有硬检查通过不表示所有 logits 逐元素 exact，也不表示已解决 CUDA 非确定性或失稳根因 |
| 改变更新方式或增加目标后，不能继续称“原裸 O” | 最终保留唯一原 KD、普通 FP16 SGD、A/B 同 LR 且均为公共 LR 的 0.1 倍、首 batch 起更新 | 不含额外 R1-reference KL、FP32 master、AB16 异速或 HARP 停更；这些历史候选不能混入最终五角色统计 |

实际结构与训练函数见 [O 参数化](../routes/larp/archive/project/trainers/efficient_adaptation.py)、[PromptKD 损失/训练/终评](../routes/larp/archive/project/trainers/promptkd.py)、[原 SGD 安装器](../routes/larp/protocol/original_sgd.py)、[共同投影器渐升](../routes/larp/protocol/projector_schedule.py)。张量维度、缩放与完整伪代码见 [LARP 实现说明](LARP_IMPLEMENTATION.md)。

旧 V/Q、混合 V/O、附加 KL、固定范数、FP32 master、A/B 异速等探索与最终主配置不是同一个实验协议；它们的覆盖并不统一为十集三 seed。本页只对包内完整逐项证据计算数值结论，不为未随包提供完整记录的历史候选补造统一成绩表，也不把“最终未采用”写成“已经证明在所有条件无效”。

## 2. 统计范围与计算方法

包内 [flat_results.json](../results/larp/flat_results.json) 有 150 个唯一角色：十集×三 seed×`R1 / O4-r1 / O4-r2 / O4-r4 / O3-r2`，对应 [epochs_index.json](../results/larp/epochs_index.json) 的 3000 个逐轮记录。最终合集中有 60 个既有主实验/控制、9 个既有末三层 seed1 记录及 81 个后续完成记录，不是本次发布重新跑了 150 次。Pets 的独立复放不计入 150 个角色。另有 [R0 外部固定参照](../results/larp/r0_external_reference.json) 的 30 条记录；它不是同期同机配对控制，也没有在本次发布重新评估。

本页独立核算了 150 条记录的 Base/Novel 正确数与总数，重算 450 个指标；R0 按所存未舍入 Base/Novel 重算 30 个 HM。结果与原分析 JSON 一致。各数据集先逐 seed 算 $HM=2BN/(B+N)$，再平均 seed1/2/3 的 HM；十集宏平均再对十个数据集等权平均。**不是先平均 Base/Novel 再取调和平均**。表中绝对 HM 单位为 `%`，差值单位为百分点 `pp`，仅显示时保留四位小数；正负判定使用未舍入值。

R1/O4 主实验有 30/30 本机配对；seed1 与 seed2/3 来自不同节点，seed 与机器没有完全交叉。R0 对比用于外部复现参照，不能把 `R1−R0` 当作纯粹的调度因果效应。[来源与机器边界](../results/larp/analysis.json)

有代表性的积极证据不是只有一个最高 seed：

- **Cars**：三个 seed 的 Base、Novel、HM 都高于本机 R1；三 seed 平均分别提高 **+0.3665、+0.6107、+0.4873 pp**，说明该任务的改善同时覆盖两端类别。
- **Flowers**：三个 seed 的 Novel 和 HM 都提高；平均 Novel **+0.3073 pp**、HM **+0.1834 pp**，平均 Base 为 **0.0000 pp**。这不是“Base/Novel 每个 seed 都提高”。
- **Aircraft、SUN**：三个 seed 的 HM 都提高，平均 HM 分别为 **+0.2966、+0.1243 pp**。Aircraft 的平均 Novel 为 **−0.0200 pp**，其 HM 改善不能改写成两端均提升。

也不能把均值正向等同于一致性：UCF 只有 **1/3** seed 的 HM 为正；Food 的平均提升只有未舍入 **+0.00240617 pp**，不据此声称稳健增益。Caltech 对 R0 的较大差值也不能全归给 LARP，须同时看其对 R1 仅 **+0.0586 pp**。

三个负向任务 DTD、Pets、EuroSAT 分别为 **−0.8169、−1.8997、−1.6325 pp**，其降幅超过七个正向任务的总增幅，故 **7/10 方向性覆盖与负的宏平均可以同时成立**。全 30 个配对中仅 18 个 HM 正向；只有 Aircraft、Flowers、Cars、SUN 四集三个 seed 都正向。不删去负向集重报“总体平均”，也不以覆盖率代替效应大小或显著性检验。[逐 seed 差与完整宏统计](../results/larp/analysis.json)

## 4. rank 与层数：存在任务取舍，不证明 rank2 最优

以下均为十集三 seed；新增参数不含共同的 1,013,760 个可训练参数。`O3-r2` 是零基层号 `[9,10,11]` 的末三层，不是历史另一组三层位置。所有 rank 固定 `alpha=1`，实际缩放为 `1/sqrt(rank)`。[固定变体](../routes/larp/protocol/variants.json)、[参数化源码](../routes/larp/archive/project/trainers/efficient_adaptation.py)

| 变体 | 新增参数 | 宏 HM | 对 R0 / pp | 对 R1 / pp | 对主 O4-r2 / pp | HM 正配对 | 双正数据集 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| O4-r1 | 6,144 | 83.2842 | −0.5877 | −0.9730 | −0.6684 | 16/30 | 4/10 |
| **O4-r2（主）** | 12,288 | 83.9526 | +0.0807 | −0.3046 | 0.0000 | 18/30 | 7/10 |
| O4-r4 | 24,576 | 84.2047 | +0.3328 | −0.0525 | +0.2521 | 16/30 | 6/10 |
| O3-r2 | 9,216 | 84.2640 | +0.3921 | +0.0068 | +0.3114 | 18/30 | 7/10 |

上述宏结果、正配对与双正计数均由逐项记录重算，与 [analysis.json](../results/larp/analysis.json) 的 `macro` 一致。

**秩的发现。** 已测 rank1→2→4 的宏 HM 是递增的，不能写成“三秩宏结果非单调”；但双正覆盖为 **4→7→6**，并不同步递增。rank4 改善了主 rank2 在 Pets/EuroSAT 的平均表现，却在 Flowers 退到对 R1 **−0.7165 pp**；rank1 虽然宏结果较差，却用主方案一半新增参数在 Cars 得到 **+0.5943 pp**，高于 rank2 的 **+0.4873 pp**。因此观察支持任务相关的容量选择，不支持 rank2 普遍最优或增加 rank 必然提高每个任务。

**层数的发现。** 末三层相对主方案减少 **25%** 新增参数，宏 HM 提高 **+0.3114 pp**，但相对 R1 仅 **+0.0068 pp**。它对原四层只在 Pets、UCF、EuroSAT 三集平均 HM 更高，其余七集较低；相对 R1 仅 Cars 三个 seed 的 HM 全正。Pets/EuroSAT 的恢复与 DTD 的进一步回退（对 R1 **−1.3347 pp**）同时保留，不能概括为少一层统一更优。删除一层也降低容量，不是纯层位置因果对照。

**比较的限制。** rank 变化同时改变参数量、矩阵形状和缩放；rank1/rank4 各有 **24/30** 与旧 R1 同机配对，另外 6 对跨机；末三层对统一主 R1 的 **30/30 都跨机**。因此同 seed 不等于同机器、同 CUDA 数值轨迹。这里报告的是已执行固定配置的观测差，不能宣称跨机数值等价、单个层的独立贡献或未经测试的全局最优。[机器/统计边界](../results/larp/analysis.json)

## 5. 训练问题与 Pets 复放：通过工程检查不等于识别提升

从完整 [3000 轮轨迹](../results/larp/epochs_index.json)抽取主实验的 30 个配对，**25/30** 的末轮加权 KD 低于 R1，但 HM 只在 **18/30** 配对提高。尤其 EuroSAT 三个 seed 的末轮 KD 都下降，而三个 seed 的所选 checkpoint HM 都下降；平均末 KD 差为 **−2.7749**，HM 差为 **−1.6325 pp**。KD 已含各集的 200/1000 权重，应作同集同 seed 配对比较，不能把不同数据集的绝对 KD 直接排名。末轮 KD 与按 Base 选出的 best HM 还来自不同测量点，因此“更低蒸馏损失”不是“识别一定更好”的替代指标。[原 KD 与选点实现](../routes/larp/archive/project/trainers/promptkd.py)

完整曲线也揭示选中 best 可能掩盖中途波动：以“相邻两轮 Base 下降至少 20 pp”作**描述性切点**，R1 为 1/30，O4-r2 为 3/30；主方案的三项是 Pets seed2、EuroSAT seed1/2。这个 20 pp 不是新设的训练放行门槛，也不把没有越过它的运行自动称为稳定。[全轨迹及描述统计](../results/larp/analysis.json)

Pets seed2 原 O4-r2 曾明显退化，随后在原节点执行了一次独立复放。原记录与复放均为 Base **91.1217%**、Novel **92.2260%**、HM **91.6705%**、best 第 16 轮；对应 R1 的 HM 为 **97.3702%**，仍相差 **−5.6997 pp**。归档显示两次初态、全 batch 记录、20 轮曲线以及 best/last checkpoint SHA 一致。这支持“该次退化可以按原条件再次发生”，不能将其归为一次偶然的坏结果后删除。[原记录与复放证据](../results/larp/main_and_replay_summary.json)

复放明确 `included_in_main=false`：**不替换原 Pets，不充当第四个 seed，不择高报告**。同时，复放报告保留 native Base 与独立重载之间非逐元素 exact 的证据（旧逐元素比较有 7 项超限，对称行尺度硬检查为 0 项超限）；原与复放的元数据文件也并非全部同字节。故“曲线/检查点一致”不应扩大为“全部输出 exact”或“普遍复现性已证明”。[保留的重载比较规则](../routes/larp/archive/helpers/larp_two_dataset_ramp_20260929/evaluation_evidence.py.txt)

## 6. 已支持什么，尚未证明什么

这些实跑支持：在固定 PromptKD 框架内，O-only 低秩更新对 Cars、Flowers、Aircraft、SUN 等任务存在可核验的识别收益；不同 rank/层数呈现具体容量—任务取舍；完整配对、全轨迹与独立复放能区分方向性覆盖、平均收益、拟合与重复性，不必只保留成功案例。

这些实跑尚未证明：相对 R1 的总体宏平均提升、所有数据集/seed 稳定改善、统计显著性、rank2 或末三层普遍最优、单个结构或调度组件的独立因果、跨机数值等价，以及训练/部署的普适提速或省显存。三 seed 的样本离散不等于置信区间；开发过程中已经见过测试表现，不能宣称严格盲测或未知分布保证。

本次发布新增的是便携入口、路径参数化与执行/证据约束，科学源码和历史成绩分别保留。**本文重算的是包内历史记录，没有新 GPU 完整训练或重评，也没有用历史成绩证明新入口已重现整条数值轨迹。** 新运行须按[复现步骤](RUN_REPRODUCTION.md)产生自己的 gate、正式训练和首次独立重载记录，并与历史 `results/` 分开。[发布核验范围](VALIDATION.md)

## 7. 逐数据集收益解释与可检验假设

下表把“发生了什么”与“可能为什么发生”分开。主方案的 ΔHM、ΔBase、ΔNovel 均为 `O4-r2−R1` 的三 seed 平均，单位为 pp；“HM 正 seed”按未舍入逐次差计算。Base/Novel 取自同一个所选 best，末轮 KD 与最大相邻 Base 降幅则描述完整训练过程，不能把两类测量当成同一时刻的因果证据。HM 对较低的一侧更敏感，但其变化仍取决于两侧各自的起点和幅度，不能只数 Base/Novel 哪一项为正。

实际 best 按 Base **测试划分**准确率选点，而非独立验证集；学生训练已接触 Novel 的无标签训练图像。因此，这些比较沿用既有协议，不是严格盲测或完全未接触新类的保证。[完整实验条件](EXPERIMENT_PROTOCOL.md)

这些解释的共同边界有三点。第一，**主实验同 seed、本机的 R1 配对支持比较完整 O4/r2 配置，却不能拆出某个参数化、FP16 行为或公共调度的独立因果效应**。第二，上表的结构结果仍保留第 4 节的来源限制：rank1/rank4 各 6/30 对跨机，末三层对统一 R1 全部跨机；rank 改变还同时改变矩阵形状与 `1/sqrt(rank)` 缩放，删层同时减少容量。第三，包内只有逐轮 Base/KD，而无逐轮 Novel；不能凭 Base 回升补画或推定新类同步恢复。

因此，后续若要验证上表假设，应在另行授权、独立登记的范围内，用同一批样本的两端错误变化、类别级差异、教师—学生分布或受控结构/数值对照去检验，而不是从数据集名称反推特征机制。当前没有新增这些实验，也不将 Cars、Flowers、DTD、EuroSAT 等分类基准的观察直接外推为车辆、农食、工业质检或遥感生产系统的效果证明。完整主差值图仍见[同源全十集图](../results/findings/main_hm_deltas.svg)，其中所有正负项保留。
